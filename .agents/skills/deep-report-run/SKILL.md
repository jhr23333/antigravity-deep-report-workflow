# 公司深度研究报告端到端总控工作流（跨平台通用版）

本 Skill 串联任意上市公司的深度研究报告全流程。**所有命令均以当前工作区/仓库根目录为工作目录、使用相对路径与 `python` 执行**，规范唯一真源位于 `脚本与规范/`。

## 必须先读的单一真源与子 Skill

- 完整 SOP 与 `00–09` 目录速查：`脚本与规范/workflow_sop.md`
- 文风、卖方口径、永久双红线与质控 12 条细则：`脚本与规范/style_guide.md`
- Word 模板样式与占位语法：`脚本与规范/report_template_spec.md`、`脚本与规范/chart_theme.json`
- 工作底稿四级梯队、门禁 2B 与六道门禁：`脚本与规范/workpaper_spec.md`
- 关联子 Skill：`deep-report-review`（Step 3.5）、`deep-report-charts`（Step 5A）、`deep-report-workpaper`（Step 5B）

## 绝对不可违背的防翻车硬约束

1. **必须冷启动**：严禁直接沿用旧长对话里的旧版盈利预测或旧稿件；在根目录下新建独立文件夹 `<公司名>/`。
2. **必须逐节落盘、严禁单回合缩水**：无论当前客户端是否支持并发子 Agent，**都必须按二级节（`1.1`、`1.2`、`2.1`…）逐节写入 `<公司名>/04_分节草稿/*.md`**，每个二级节不少于 3–4 段、每段 200–300 字（不超过 350 字）、图/表穿插；**严禁一口气输出一份 8–10 页的压缩简报**（成稿图表数低于大纲拟定数 75% 会被 `sync_check.py` 🔴 拦截）。
3. **必须实跑仓库脚本与内置官方模板**：图表必须用 `chart_maker.py` 生成，Word 必须用 `render_docx.py` 套用 `模板资产/国金证券_公司深度研究模板.docx`，底稿必须用 `build_workpaper.py` 套用 `模板资产/国金研报工作底稿模板.xlsx`；**严禁绕过脚本手搓无模板文档**。
4. **严禁代填盈利预测**：除用户明确提供模型数字外，所有盈利预测、EPS、PE、目标价与评级一律保持 `[待模型填入]`。

## 端到端 6 步执行流程

### Step 1：立项建目录、全量取数与近 90 天公告扫描
1. 建立目录：`<公司名>/00_原始资料/pdfs/`、`<公司名>/00_原始资料/内部参考_禁入底稿/`、`<公司名>/04_分节草稿/`、`<公司名>/07_图表/`、`<公司名>/08_底稿证据/`。
2. **基础财务/行情优先用当前可用数据源，并做近 90 天公告交叉核对**：
   - 常规财务与同业对比优先走当前可用终端（**iFinD / Choice / Wind / SEC 20-F / 官方财报**，合规金融数据库在底稿免截图）；
   - **近 90 天全量公告无过滤扫描**：拉取公司最近 90 天全部临时公告/披露标题清单（禁止只按单一关键词过滤），防漏经营进展、自建基地开工、再融资/回购等关键催化；
   - **股本与实控人持股以最新发行/权益变动公告 PDF 为唯一真源**；最新季报同步核查**交易性金融资产（广义现金）**、**所得税费用/少数股东损益**，并反推最新单季毛利率与单季经营现金流。
3. **按需下载 2–3 份核心公开 PDF**（最新季报/年报/招股书/20-F/重大经营公告），用于核查非标准附注明细与底稿整句红框截图。
4. 若为 A 股季报/年报 PDF，运行精确抽数脚本（港美股或已有 Choice/iFinD 完整数据时按需跳过）：
   ```bash
   python 脚本与规范/pull_company_data.py \
     --name <公司名> --code <股票代码> \
     --pdf <公司名>/00_原始资料/pdfs/<最新财报>.pdf \
     --out <公司名>/00_原始资料/01_最新财报全科目快照.md
   ```
5. 产出共享锚点 `<公司名>/01_全篇主线卡与禁重分工表.md` 与 `<公司名>/02_统一术语与数字口径表.md`；如环境配了知识星球 MCP，可同步摸底市场观点落盘至 `内部参考_禁入底稿/`（物理隔离严禁入正文/底稿）。

### Step 2：两阶段精准联网与段落级论点大纲（硬闸门：必须等研究员拍板）
- 边搜边产出 `<公司名>/03_段落级大纲.md` 与 `<公司名>/00_原始资料/02_行业公开数据包.md`：
  - 章节数量按公司业务结构灵活设定（不锁死五章），**每个二级节不少于 3–4 段**，标题均为论点句；
  - **两阶段强制联网检索 + 一手 URL 落盘**：① 一阶段宽搜定框架 → 二阶段对每个核心行业数字、技术协议/物理规格及海外竞品财报做单点深搜核验，并加近两月词核查有无更新预测；② 在 `02_行业公开数据包.md` 落盘**真实文章页 URL 或海外官方 IR PDF 链接 + `must_contain` 核验词**（严禁只记根域名；海外官网遇 WAF/403 时优先找官方 IR PDF 或同步锁定国内白名单财经/电子媒体转引页）。
- **硬闸门**：必须把 `03_段落级大纲.md` 展示给研究员确认后再进入 Step 3。

### Step 3：逐节撰稿与统稿汇总
- 有子 Agent 工具时按章并发，**无子 Agent 工具（如 ChatGPT Work 单对话框）时按二级节顺序逐节写入 `<公司名>/04_分节草稿/<节号>.md`**，每节落盘确认字数与图数达标后再写下一节。
- **文风与合规硬约束**（详见 `脚本与规范/style_guide.md`）：
  - **永久写作双红线**：**正文严禁连续堆砌逐年/逐季历史数据清单**（具体序列留给图表与表格，正文只点 1–2 个最新锚点并聚焦趋势与因果推演）；**严禁分析财务费用率**（费用率分析与图表均不单列财务费用率）；
  - 整体采用**建设性/偏乐观卖方深度框架**，不写成偏空买方质询腔；不写无公开出处的定性狠话，确有一手出处的硬判断须同步建 `type: "text"` 底稿；
  - 严禁引用友商卖方研报及非白名单论坛/自媒体；盈利预测/估值/目标价保持 `[待模型填入]`。
- 合并统稿生成 `<公司名>/05_完整初稿.md`、`<公司名>/report_meta.json`（首页摘要 `≤ 850 字` 且不提未覆盖可比公司名）、`<公司名>/charts.json` 与 `<公司名>/06_证据清单.json`。

### Step 3.5：独立红队审稿（调用 `deep-report-review`，严禁跳过）
- 按 `deep-report-review` Skill 运行 `redteam_review.py` 生成带 `draft_sha256` 的 `05_红队审稿任务包.md`，完成六维独立联网红队审稿并落盘 `05_红队审稿意见.md`，按审稿硬伤完成定点修订。

### Step 4：研究员复核确认（保留 `[待模型填入]`）
- 由研究员审定修订后的正文逻辑与事实；盈利预测与估值保持 `[待模型填入]`，留待产出 Word 后自行刷模型填入。

### Step 5：一键制图、对账、套模板 Word 与红框底稿打包
- 依次严格执行 `deep-report-charts` 与 `deep-report-workpaper` 中的全部 Python 命令；
- **默认交付标准（`--strict`）**：三端全部通过 `--strict`（`exit code = 0`，0 🔴 错误，自动输出 `<公司名>/09_对账与质检报告.md`），允许保留 `[待模型填入]`；仅确经四级梯队尝试且有 `attempted_urls` 留痕的闭源付费报告允许标黄 `[INCOMPLETE]`（严禁未抓先弃）。
